Lektion 131

Event från SQS

Vad du ska veta efter lektionen Att eventet från SQS har listan Records med en post per meddelande, att body är en sträng som du tolkar med JSON.parse, och att attributes.ApproximateReceiveCount säger vilket försök det är.

Hur ser eventet ut?

Eventet är ett objekt med nyckeln Records, en lista med en post per meddelande. Triggern hämtar meddelandena och lägger dem i listan, så listan kan ha flera poster. (AWS: Lambda med SQS)

I lektion 83 gjorde API Gateway om anropet till ett event. Här bygger Lambda strukturen. Av innehållet är bara body skrivet av producenten.

Vilka fält behövs?

Två fält i varje post: body och attributes.ApproximateReceiveCount. Båda är strängar. Så ser en post ut, förkortad: (AWS: Lambda med SQS)

{
  "Records": [
    {
      "body": "{\"id\":\"c-1042\",\"name\":\"Test Testsson\"}",
      "attributes": { "ApproximateReceiveCount": "1" }
    }
  ]
}

body är meddelandets innehåll som text, även när texten är JSON, precis som event.body i lektion 83. Därför tolkas den med JSON.parse. Receive count heter ApproximateReceiveCount i eventet och är texten "1", inte talet 1.

Koden går igenom listan post för post. Per post tolkar den JSON.parse(record.body) och läser record.attributes.ApproximateReceiveCount. Fältet attributes är det SQS själv lägger till om meddelandet.

Sammanfattning

  • Eventet har listan Records, en post per meddelande.
  • body är en sträng. JSON tolkas med JSON.parse.
  • attributes.ApproximateReceiveCount är en sträng med antalet hämtningar.
