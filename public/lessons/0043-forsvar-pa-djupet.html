Lektion 43

Försvar på djupet

Vad du ska veta efter lektionen Att försvar på djupet betyder flera skyddslager kring databasen, och att ett enda stängt lager hade stoppat angreppet i caset.

Vad är försvar på djupet?

Försvar på djupet betyder att du skyddar databasen med flera lager efter varandra. En angripare måste igenom alla. Ett misstag räcker då inte. (AWS: Security pillar, design principles)

Lagren är ditt ansvar (lektion 19). Även backup: AWS tar den, men du väljer hur många dagar den sparas.

Vad hände i caset?

Ett företag sparar kvitton i RDS. En måndag är databasen tom. Kvar finns ett krav på pengar. Fem lager stod öppna:

LagerI casetHade stängt räckt?
PlaceringPublikt subnät, Public access: YesJa Ingen publik adress, ingen väg in.
Security group5432 från 0.0.0.0/0Ja Bara webbserverns grupp kommer in.
LösenordEtt vanligt lösenordDelvis. Program provar miljontals per dygn.
Backup0 dagar, så ingen tasNej. Datan stjäls, men kravet blir meningslöst.
ÖvervakningCloudWatch visade 40 anslutningar på natten. Ingen tittade.Nej, men upptäckt på natten.

(kursens lektion sida 25, 26 och 28; AWS: Backup retention period)

Varför räckte ett lager?

Angreppet behövde en väg in till port 5432. Placering och security group stänger den var för sig. Backup och övervakning stoppar inget, de minskar skadan.

Kursens databas stänger båda: privata subnät, Public access: No, och 5432 bara från webbserverns grupp.

Vad som hade räckt

Ett enda stängt lager hade räckt. Fem var öppna. (kursens lektion sida 28 och 37)

3. Repetition från lektion 35: vilken källa ska regeln för 5432 i databasens grupp ha?

Sammanfattning

  • Försvar på djupet är flera skyddslager efter varandra: placering, security group, lösenord, backup och övervakning. Lagren är ditt ansvar.
  • I caset stod alla fem öppna. Ett enda stängt lager, placering eller security group, hade stoppat angreppet.
  • Backup och övervakning stoppar inget, men gör skadan mindre: kravet på pengar blir meningslöst och angreppet upptäcks tidigt. Databasen står i privata subnät med Public access: No och tar bara in webbservern.

Källor

Huvudkälla: AWS Well-Architected Framework, Security pillar: Design principles (Apply security at all layers).

Om backup: Backup retention period. Om övervakning: Amazon CloudWatch metrics for Amazon RDS (DatabaseConnections).
