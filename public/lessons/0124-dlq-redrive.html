Lektion 124

DLQ redrive

Vad du ska veta efter lektionen Att DLQ redrive flyttar meddelanden från dödbrevskön tillbaka till huvudkön, och att de där räknas som nya meddelanden.

Vad är DLQ redrive?

DLQ redrive flyttar meddelanden från dödbrevskön tillbaka till huvudkön, som också kallas källkön. Det gör du när felet är rättat och meddelandena ska få nya försök. SQS ändrar eller filtrerar inte meddelandena på vägen. (AWS: DLQ redrive)

I konsolen startas redrive från dödbrevskön, inte från huvudkön: Start DLQ redrive, Redrive to source queue(s) och sedan Redrive messages.

Vad händer med meddelandet?

Ett redrivet meddelande räknas som ett nytt meddelande. Det får ett nytt message ID, och retention-perioden börjar om. I lektion 121 räknades tiden i dödbrevskön från första skickandet, men redrive nollställer den. (AWS: DLQ redrive)

Inte bekräftat av AWS I konsolen visas receive count som 0 efter redrive. AWS dokumentation säger inte det.

Sammanfattning

  • DLQ redrive flyttar meddelanden från dödbrevskön tillbaka till huvudkön (källkön) utan att ändra innehållet.
  • Start DLQ redrive finns på dödbrevskön.
  • Ett redrivet meddelande räknas som nytt: nytt message ID, och retention-perioden börjar om.
