Lektion 70

Mixed content

Vad du ska veta efter lektionen Varför din sida på Amplify, som har HTTPS, inte får anropa ditt API över HTTP, och att API Gateway löser det i v42.

Vad är HTTPS?

HTTPS är HTTP med kryptering. Ingen på vägen kan läsa eller ändra anropet och svaret. Med HTTP går allt som klartext. (MDN: Mixed content)

Din sida på Amplify har en adress som börjar med https://. Ditt API på EC2 nås bara med http://. (kursens lektion sida 18)

Vad stoppar webbläsaren?

Webbläsaren stoppar anrop över HTTP från JavaScript på en sida som laddats över HTTPS. Annars kunde någon på vägen läsa eller ändra det sidan skickar och får. Att en HTTPS-sida hämtar något över HTTP kallas mixed content. (MDN: Mixed content)

Anropet lämnar aldrig webbläsaren. I Network-fliken står det blocked:mixed-content, och koden får Failed to fetch. (kursmaterialet v41)

CORS

Servern svarar, men koden får inte läsa. En header löser det.

Mixed content

Anropet når aldrig servern. Ingen header löser det.

Hur löser API Gateway det?

API Gateway ger ditt API en HTTPS-adress. Det är en AWS-tjänst som tar emot anropen och skickar dem vidare till ditt API. Den har bara HTTPS-adresser. (AWS: Data encryption in API Gateway, AWS: HTTP proxy integrations)

Sidan anropar API Gateway över HTTPS, och API Gateway skickar anropet till servern på EC2. I sidans kod byts bara API:ets adress. (kursmaterialet v41)

Sammanfattning

  • HTTPS är HTTP med kryptering. Sidan på Amplify har HTTPS, API:et på EC2 bara HTTP.
  • Mixed content: en HTTPS-sida får inte anropa något över HTTP. Webbläsaren stoppar anropet innan det skickas, och ingen header från servern hjälper.
  • API Gateway har bara HTTPS-adresser och skickar anropen vidare till ditt API. Det löser problemet.

Källor

Huvudkälla: MDN: Mixed content.

Om API Gateway och HTTPS: AWS: Data encryption in Amazon API Gateway.
