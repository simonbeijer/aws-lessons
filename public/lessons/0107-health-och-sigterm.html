Hur vet omvärlden att API:et lever, och hur stoppas det?

Kort sagt Två små tillägg gör att API:et går att övervaka och stoppa i en container: en adress som svarar på om programmet lever, och kod som tar emot beskedet att stoppa och avslutar i ordning. Utan dem kan ett friskt API se sjukt ut, och ett stopp avbryter anrop mitt i. Båda ska finnas innan API:et packas.

Vad är /health?

/health är en adress i API:et som bara svarar på om processen lever. Den frågar inte databasen. Svaret är statuskod 200 med {"status":"ok","version":"1.0.0"}.

Skälet är att en lastbalanserare i v45 ska fråga adressen för att veta om API:et fungerar. Skulle /health också fråga databasen, räknades API:et som dött varje gång databasen har problem, fast programmet är helt friskt.

Därför kan /health ge 200 samtidigt som /customers ger 500: når API:et inte databasen misslyckas /customers, men /health svarar ändå. Det syns första gången imagen startas, i lektion 109.

Vad händer vid docker stop?

docker stop skickar SIGTERM (Signal Terminate) till containerns huvudprocess, alltså API:et. En signal är ett kort besked till en process, och SIGTERM betyder "avsluta dig".

En huvudprocess i en container avslutas inte av SIGTERM om den inte har kod för det. Då händer inget, Docker väntar 10 sekunder och skickar SIGKILL (Signal Kill). Det kan programmet inte fånga, det dör direkt, också mitt i ett anrop.

Hur avslutar API:et i ordning?

API:et lyssnar på signalen med process.on("SIGTERM", ...). När den kommer sker tre saker i tur och ordning:

  • server.close() slutar ta emot nya anslutningar, men låter pågående anrop bli klara.
  • När alla är klara stängs anslutningarna till databasen med pool.end().
  • process.exit(0) avslutar programmet.

I loggen syns SIGTERM: stänger, och docker stop är klart på en bråkdels sekund i stället för tio.

Quiz

1. /health ger 200 och /customers ger 500. Vad säger det?

2. Ett API utan SIGTERM-kod stoppas med docker stop. Vad händer?

3. API:et har SIGTERM-kod och är mitt i ett anrop när docker stop körs. Vad händer med anropet?

Sammanfattning

  • /health svarar på om processen lever, utan att fråga databasen. Därför ger den 200 fast /customers ger 500.
  • docker stop skickar SIGTERM till huvudprocessen. Utan kod för den väntar Docker 10 sekunder och skickar SIGKILL, som inte går att fånga.
  • Med process.on("SIGTERM", ...) slutar API:et ta emot nya anrop (server.close()), låter pågående bli klara, stänger databasanslutningarna och avslutar.

Källor

Huvudkälla: Docker: docker container stop (SIGTERM, 10 sekunder, SIGKILL). Att en huvudprocess inte avslutas av SIGTERM utan kod för det: Docker: docker container run. Att SIGKILL inte kan fångas och process.on: Node.js: Signal events. server.close(): Node.js: server.close. Koden i /health och SIGTERM-hanteraren, svaret med version och att /health inte ska fråga databasen kommer från kursen. Att 0 är lyckat avslut (Node.js kallar 0 "the success code"): Node.js: process.exit.
