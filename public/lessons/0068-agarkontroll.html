Lektion 68

Ägarkontroll

Vad du ska veta efter lektionen Att en inloggad bara får sina egna resurser, till exempel sina egna bokningar, och att någon annans ska ge 404, samma svar som om den inte fanns.

Vad är ägarkontroll?

Ägarkontroll är att servern kontrollerar att det du hämtar är ditt. Autentisering svarar på vem du är. Att kontrollera vad du får hämta kallas auktorisering. Ägarkontroll är auktorisering per bokning. (MDN: 403 Forbidden, kursens lektion sida 27)

Anna loggar in och hämtar sin bokning med GET /bookings/42. Ändrar hon sökvägen till /bookings/43 är hennes token fortfarande giltig. Utan ägarkontroll får hon då någon annans bokning. (OWASP: Broken Object Level Authorization)

Därför ska servern kontrollera ägaren i varje anrop som hämtar något med ett id. (OWASP: Broken Object Level Authorization)

Vilket svar ska ges?

Någon annans bokning ska ge 404 Not Found, samma svar som om bokningen inte fanns. Så svarar servern på tre anrop: (kursens lektion sida 29)

AnropSvar
GET /bookings/43 utan token401
GET /bookings/43 med Annas token, bokningen är Bennys404
GET /bookings/42 med Annas token, bokningen är hennes200

Varför samma svar?

Samma svar gör att ingen kan räkna bokningarna. Id:n är 1, 2, 3 i tur och ordning. Om andras bokningar gav 403 Forbidden och saknade gav 404, kunde vem som helst prova id efter id och se vilka som finns. (kursens lektion sida 25 och 29, MDN: 403 Forbidden)

403 är alltså ett korrekt svar, men det avslöjar att bokningen finns. Statuskoden är en del av säkerheten. (MDN: Access forbidden, kursens lektion sida 29)

Gör så här

Lägg till ett negativt test: Annas token och Bennys bokning ska få 404.

Quiz

1. Anna är inloggad och hämtar Bennys bokning. Vad ska servern svara?

2. Varför svara 404 och inte 403 på någon annans bokning?

3. Repetition från lektion 53: Var står det vilken bokning GET /bookings/43 hämtar?

Sammanfattning

  • Ägarkontroll är att servern kontrollerar att det du hämtar är ditt. Autentisering säger vem du är, ägarkontrollen vad du får hämta.
  • En giltig token räcker inte. Servern ska kontrollera ägaren i varje anrop som hämtar något med ett id.
  • Någon annans bokning ger 404, samma svar som om den inte fanns, så att ingen kan räkna vilka som finns.

Källor

Huvudkälla: OWASP API Security: Broken Object Level Authorization.

Om 403 och 404: MDN: 403 Forbidden.
