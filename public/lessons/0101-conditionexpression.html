Lektion 101

ConditionExpression

Vad du ska veta efter lektionen Att attribute_exists(id) hindrar UpdateItem och DeleteItem från att gälla ett item som inte finns, och att felet då görs om till 404.

Vad är ett villkor?

Ett villkor är ett uttryck som måste vara sant för att en skrivning ska göras. Det skickas i ConditionExpression. DynamoDB testar villkoret mot itemet med id:t i Key. Är villkoret falskt ändras inget, och anropet misslyckas. (AWS: Condition expressions)

attribute_exists(id) är sant bara om itemet har attributet id. Varje item har id, eftersom det är partitionsnyckeln. Villkoret betyder alltså: itemet måste finnas. (AWS: Checking for attributes)

Varför behövs villkoret?

Villkoret behövs eftersom UpdateItem och DeleteItem annars inte märker att id:t saknas. UpdateItem skapar då ett nytt item med bara id och name. DeleteItem tar inte bort något men ger inget fel, så koden svarar som om kunden togs bort. Med villkoret misslyckas båda i stället. (AWS: UpdateItem, AWS: DeleteItem)

PUT /customers/finns-inte   { "name": "Carol" }

Nytt item: { id: "finns-inte", name: "Carol" }

Fel En kund som aldrig fanns skapas.

PUT /customers/finns-inte   { "name": "Carol" }

ConditionalCheckFailedException

Fungerar Inget skapas, och klienten får 404.

Hur blir felet 404?

När villkoret är falskt kastar anropet ett fel med namnet ConditionalCheckFailedException. Ett try/catch fångar felet och returnerar 404, att kunden inte finns. Alla andra fel kastas vidare med throw och blir ett 5xx-fel. (AWS: Error handling with DynamoDB)

try {
  await db.send(new UpdateCommand({
    TableName: "v42-customers",
    Key: { id },
    UpdateExpression: "SET #n = :n",
    ExpressionAttributeNames: { "#n": "name" },
    ExpressionAttributeValues: { ":n": name },
    ConditionExpression: "attribute_exists(id)",   // itemet måste finnas
  }));
} catch (err) {
  if (err.name === "ConditionalCheckFailedException") {
    return {
      statusCode: 404,
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ error: "customer not found" })
    };
  }
  throw err;   // allt annat blir ett 5xx-fel
}

DeleteItem får samma villkor och samma catch. (AWS: DeleteItem)

Quiz

3. Repetition från lektion 98: vad får klienten om ett kastat fel inte fångas?

Sammanfattning

  • Ett villkor i ConditionExpression måste vara sant, annars ändras inget och anropet misslyckas.
  • UpdateItem skapar ett item om det inte finns. attribute_exists(id) förhindrar det, eftersom det kräver att itemet finns. DeleteItem använder samma villkor.
  • Felet som kastas heter ConditionalCheckFailedException. try/catch gör om det till 404. Andra fel blir 5xx.
