Hur säger man åt AWS att köra en container?

Kort sagt Imagen från V44 ligger i AWS men körs ingenstans. ECS är tjänsten som kör den, och i stället för flaggor som till docker run vill den ha ett recept, en task definition. Receptet kommer först, för utan det kan inget startas.

Vad gör ECS?

ECS (Elastic Container Service) startar containrar från en image i ECR (Elastic Container Registry), där imagen från V44 ligger. På datorn skrev du image, port och variabler i docker run eller i compose.yaml. I AWS står samma uppgifter i receptet, så koden ändras inte.

Containrarna körs i Fargate, vilket betyder att AWS äger servrarna och du sköter ingen dator. Ett kluster är bara ett namn att samla det som körs under.

Vad står i receptet?

Receptet är en JSON-fil. Klicka på en del för att se vad den motsvarar på datorn.

Imagen anges med hela adressen i ECR: kontonummer, region och v44-api:latest, med taggen. Storleken är 0,25 vCPU (virtual CPU, en fjärdedels processorkärna) och 0,5 GB minne. Operativsystemet är Linux och processorn X86_64, samma sak som amd64. Det måste stämma med imagen, som byggdes för linux/amd64, annars startar den inte.

Container port är porten API:et lyssnar på, 3000. Miljövariablerna är samma som -e, här DB_HOST mot RDS (Relational Database Service) och de andra. DB_SSL utelämnas: RDS har certifikat, så koden slår på SSL (Secure Sockets Layer) av sig själv. Lösenordet står i klartext i receptet. AWS avråder från det för känsliga värden och har fältet secrets för dem.

Containerns stdout, det docker logs läste, skickas med awslogs till CloudWatch Logs, i loggruppen /ecs/v45-api.

Vilka roller behövs?

Receptet pekar också ut två IAM-roller (Identity and Access Management). De låter lika men används av olika parter.

  • Execution role använder ECS själv, för att hämta imagen från ECR och skriva loggarna. Containern kommer inte åt den.
  • Task role är rollen koden får när den anropar AWS. Den är tom tills vidare, eftersom API:et inte anropar något AWS-API.

Hur ändrar man receptet?

Ett registrerat recept ändras aldrig. Varje ändring, till exempel en ny miljövariabel, blir en ny revision: v45-api:1, sedan v45-api:2. Namnet före kolonet är receptets familj, siffran efter är revisionen.

Quiz

1. ECS ska hämta imagen ur ECR. Vilken roll gör det?

2. Du ändrar DB_HOST i receptet v45-api:1. Vad blir resultatet?

3. Vad i receptet motsvarar -e DB_HOST=... i docker run?

Sammanfattning

  • ECS startar containrar från en image i ECR, i Fargate där AWS äger servrarna. Klustret är ett namn att samla dem under.
  • Task definition är receptet: image, storlek (0,25 vCPU, 0,5 GB, Linux/X86_64), Container port 3000, miljövariabler mot RDS och awslogs till /ecs/v45-api. Lösenordet i variablerna står i klartext.
  • Execution role används av ECS för att hämta imagen och skriva loggar. Task role är kodens egen och tom än så länge.
  • Varje ändring blir en ny revision: v45-api:1, :2.

Källor

Huvudkälla: AWS: Task definition parameters (storlek, arkitektur, miljövariabler, awslogs, task role, revisioner). Execution role: AWS: Task execution IAM role. Task definition: AWS: Task definitions. Kluster och Fargate: AWS: Clusters. Containerns namn, port och loggruppen /ecs/v45-api kommer från kursen. Priset för Fargate är inte kontrollerat och står inte här.
