Hur ser man vad som händer i en container?

Kort sagt En container som kör i bakgrunden visar ingenting av sig själv. Du läser vad programmet skrivit, eller kör ett kommando inne i containern. Så ser du om containern du nyss startade gör det den ska.

Hur läser man loggen?

Programmet i en container skriver ut text, som en webbserver gör för varje anrop. Texten går till stdout (standard output, vanliga utskrifter) och stderr (standard error, felmeddelanden). Docker samlar upp båda. Det är loggen.

docker logs web visar loggen för containern som fick namnet --name web. Du får det som finns just då: för nginx en rad per anrop, och en 404 när sidan saknas. Med -f (follow) fortsätter kommandot visa nya rader när de kommer, tills du avbryter med Ctrl+C.

Skriver programmet sin logg till en fil inne i containern syns den inte i docker logs.

Hur kör man något inne i den?

docker exec kör ett nytt kommando i en container som redan kör, utan att starta en ny:

docker exec web cat /usr/share/nginx/html/index.html

Det fungerar bara medan containerns huvudprocess kör, programmet containern startades med, här nginx. När den avslutas stoppar containern.

När behövs -it?

Vill du inte köra ett enstaka kommando utan arbeta i containern får du ett skal, ett program där du skriver kommandon och ser svaren: docker exec -it web sh. Det kräver två flaggor. -i (interactive) håller STDIN (standard input, det du skriver) öppet. -t (tty) ger skalet en terminal, så att det visar prompt och rader som i en vanlig terminal. Prompten byter utseende: du är inne i containern, som root (administratören), och exit tar dig ut igen.

Ett enstaka kommando som cat ovan behöver ingetdera, det skriver sitt svar och är klart.

Quiz

1. Programmet i en container skriver sin logg till en fil inne i containern. Vad visar docker logs?

2. Du vill se nya loggrader dyka upp medan du själv laddar om en sida. Vad gör du?

3. Du vill bara skriva ut en fil som ligger i den körande containern web. Vad behöver du?

Sammanfattning

  • Programmet skriver loggen till stdout och stderr, Docker samlar upp den och docker logs web läser den. -f följer den löpande, avbryt med Ctrl+C. En loggfil i containern syns inte.
  • docker exec web <kommando> kör ett kommando i en container som redan kör, så länge dess huvudprocess kör.
  • -it behövs bara för ett skal: docker exec -it web sh. -i håller STDIN öppet, -t ger en terminal.

Källor

Huvudkälla: Docker: docker container logs. Insamlingen av stdout och stderr: Docker: Logs and metrics. exec, -i, -t och huvudprocessen: Docker: docker container exec. Att en loggfil i containern inte syns i docker logs och att ett enstaka kommando går utan -it följer av Docker-dokumentationens beskrivningar, men står där inte uttryckligen. Det kommer från kursen, liksom loggraderna för nginx och att prompten byter utseende.
