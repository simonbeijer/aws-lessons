Vad står i en Dockerfile?

Kort sagt En Dockerfile är receptet som gör API:et till en image, åtta rader som går att läsa en i taget. Med den kan vem som helst bygga exakt samma image, och den avgör både vad som finns i imagen och vad som körs när containern startar.

Vad är en Dockerfile?

En Dockerfile är en textfil, utan filändelse, som Docker läser uppifrån och ned för att bygga en image. API:ets recept ser ut så här:

FROM node:22-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
USER node
EXPOSE 3000
CMD ["node", "server.js"]

Raderna följer en berättelse: först utgångspunkten, sedan att få in appen, till sist hur den körs.

Hur kommer appen in?

FROM node:22-alpine väljer basimagen, en färdig image som resten bygger på. Här har den Linux (Alpine) och Node 22, så ingen behöver installera Node själv.

WORKDIR /app väljer mappen som raderna efter arbetar i. Saknas den skapas den.

COPY kopierar filer från projektmappen in i imagen. Först paketfilerna (package*.json är både package.json och package-lock.json), sedan med COPY . . resten av projektet. Att ordningen har ett skäl kommer i en senare lektion.

RUN npm ci --omit=dev kör ett kommando under bygget. npm ci installerar paketen utifrån package-lock.json, som listar vilka versioner som gäller, och ändrar varken den eller package.json. Saknas lock-filen, eller stämmer den inte med package.json, avslutas kommandot med fel. --omit=dev hoppar över paket som bara behövs under utveckling.

Hur körs den?

Raderna hittills har byggt innehållet. De tre sista lägger bara till uppgifter om imagen, så kallad metadata, och ändrar inga filer.

USER node byter användare. Utan raden kör containern som root, den användare i Linux som får göra allt. Basimagen har redan användaren node, och i containern visar whoami node.

EXPOSE 3000 dokumenterar bara att API:et lyssnar på 3000. Porten öppnas inte av den: det gör -p vid docker run.

CMD ["node", "server.js"] säger vad som körs när containern startar.

RUN eller CMD?

RUN körs en gång, under bygget, och resultatet, de installerade paketen, följer med imagen. CMD körs inte under bygget. Det körs varje gång en container startar.

Hakparenteserna i CMD spelar roll. Med dem startar Docker Node direkt, så docker stop skickar SIGTERM till Node. Skriver man CMD node server.js körs kommandot via skalet /bin/sh -c. Det tar emot signalen i stället, SIGTERM-koden i API:et körs inte och Docker dödar processen efter 10 sekunder.

Quiz

1. När körs RUN npm ci --omit=dev?

2. Dockerfilen har EXPOSE 3000, och containern startas med docker run utan -p. Går API:et att nå på värdens port 3000?

3. Varför är CMD ["node", "server.js"] bättre än CMD node server.js för API:et?

Sammanfattning

  • Dockerfilen läses uppifrån. FROM väljer basimagen, WORKDIR mappen, COPY kopierar in filer och RUN kör ett kommando under bygget.
  • npm ci --omit=dev installerar utifrån package-lock.json, avslutas med fel om den inte stämmer med package.json, ändrar ingen av dem och hoppar över utvecklingspaket.
  • USER node byter från root. EXPOSE 3000 dokumenterar bara porten, -p öppnar den.
  • CMD körs när containern startar, inte under bygget. I exec-form (["node", "server.js"]) får Node SIGTERM, i skalform tar skalet den.
