Hur kan samma image köra på datorn och i AWS?

Kort sagt API:et får sina inställningar utifrån i stället för att själv veta var det körs. Då kan samma image köra på din dator och i AWS, och bara inställningarna skiljer. Det är första steget i att göra API:et från v41 redo att packas till en egen image.

Vad ska skilja?

I v41 låg allt fast i API:et: databasen, användaren, porten och SSL (Secure Sockets Layer), krypteringen mot databasen i RDS (Relational Database Service). Det går inte när samma image ska köra på din dator, mot en databas i en container, och i ECS (Elastic Container Service), AWS tjänst för containrar.

Därför står inget av det i koden eller imagen. API:et läser det ur miljövariabler, namn med värden som programmet får utifrån, via process.env, Node.js lista över dem.

Standardvärde eller inget?

API:et läser sju: PORT, DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD och DB_SSL. Fyra har standardvärde: PORT 3000, DB_PORT 5432, DB_NAME labdb och DB_USER labadmin.

Number(process.env.PORT ?? 3000)

?? ger värdet till höger bara när det till vänster saknas, så utan PORT blir porten 3000.

DB_HOST och DB_PASSWORD saknar standardvärde med flit. Adressen skiljer mellan datorn och RDS, och lösenordet hör inte hemma i koden. Saknas DB_HOST väljer databasbiblioteket pg localhost, som i en container är containern själv, och loggen visar ECONNREFUSED (connection refused).

DB_SSL och -e

SSL stängs av bara när DB_SSL är exakt strängen "false". Allt annat, också 0 eller en saknad variabel, sätter på det. Databasen i containern har inget certifikat och svarar "The server does not support SSL connections".

Du skickar in en variabel med -e (--env). kundregister-api:1 är API:ets image, byggd senare i veckan:

docker run --rm -e PORT=4000 -p 4000:4000 kundregister-api:1

Koden lyssnar på 4000, och -p kopplar värdens 4000 dit.

Quiz

1. Du startar API:ets image utan -e PORT. Vilken port lyssnar det på?

2. Du kör mot databasen i en container, utan certifikat, med -e DB_SSL=0. Vad händer?

3. Samma API ska flyttas från datorn till ECS. Vad ändras?

Sammanfattning

  • Samma image körs på datorn och i ECS. Bara miljövariablerna skiljer, och koden läser dem med process.env.
  • PORT 3000, DB_PORT 5432, DB_NAME labdb och DB_USER labadmin har standardvärde via ??. DB_HOST och DB_PASSWORD saknar det med flit.
  • DB_SSL stänger av SSL bara som exakt "false".
  • -e NAMN=värde skickar in en variabel till containern.

Källor

Huvudkälla: Docker: docker container run (-e). process.env: Node.js: process.env. ??: MDN: Nullish coalescing. Att pg använder localhost som standardvärde för host: node-postgres: Connecting. Att SSL står för Secure Sockets Layer: MDN: SSL. Variablerna, standardvärdena, DB_SSL-regeln och de två felmeddelandena kommer från kursen.
