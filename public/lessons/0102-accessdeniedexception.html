Lektion 102

AccessDeniedException

Vad du ska veta efter lektionen Hur du läser felet: vem som nekades, vilken handling och på vilken resurs. Du vet också att felet betyder att rollen saknar en behörighet.

Vad är AccessDeniedException?

AccessDeniedException är felet AWS svarar med när den som anropar saknar behörighet. Tar du bort tabellens policy från funktionens execution role och kör en Scan, kastar anropet felet. Det hamnar i CloudWatch Logs: (AWS: Troubleshoot access denied error messages)

AccessDeniedException: User: arn:aws:sts::123456789012:assumed-role/v42-api-role-abc123/v42-api
is not authorized to perform: dynamodb:Scan on resource:
arn:aws:dynamodb:eu-north-1:123456789012:table/v42-customers
because no identity-based policy allows the dynamodb:Scan action

Via API Gateway får klienten bara ett 5xx-fel med Internal Server Error, utan detaljer.

Vem, vad och på vad?

Felet säger vem som nekades, vilken handling och på vilken resurs. Klicka på delarna. (AWS: Access denied error message examples)

assumed-role/v42-api-role-abc123/v42-api är en roll som någon tagit på sig, här funktionens execution role. Lambda tar på sig den med sts:AssumeRole, därav sts i ARN:et. Först står rollens namn och sist sessionens, här funktionens. En session är en gång då rollen används. (AWS: IAM ARNs)

dynamodb:Scan är handlingen som nekades, skriven tjänst:operation som i policyn.

Resursen är tabellens ARN. Samma ARN ska stå i policyns Resource.

Vad betyder felet?

Felet betyder alltid att rollen saknar en behörighet. Slutet säger att ingen identity-based policy, alltså ingen policy som sitter på rollen, tillåter Scan. (AWS: Identity-based policies, implicit denial)

Två orsaker är vanligast: policyn sitter inte på rollen, eller ARN:et i policyn pekar på fel tabell. Jämför ARN:et i felet med det i policyn, tecken för tecken. Behörigheten läggs till i rollen i IAM. (AWS: Update the execution role)

Sammanfattning

  • AccessDeniedException syns i CloudWatch Logs. Klienten får bara ett 5xx-fel.
  • Felet säger vem (assumed-role/..., funktionens execution role), vad (dynamodb:Scan) och på vad (tabellens ARN).
  • Det betyder alltid att rollen saknar en behörighet. Kontrollera att policyn sitter på rollen och att ARN:et i policyn är rätt.

Källor

Huvudkälla: AWS IAM: Troubleshoot access denied error messages.

Om ARN för en roll som tagits på sig: AWS IAM: IAM identifiers. Om att ändra rollen: AWS Lambda: Viewing and updating permissions in the execution role.
