Lektion 103

HTTP API

Vad du ska veta efter lektionen Vilka fyra saker API Gateway gör med ett anrop på väg till din funktion, och varför du bygger ett HTTP API och inte ett REST API.

Vad är ett HTTP API?

Ett HTTP API är en av API-typerna i API Gateway. Det tar emot anrop och skickar dem vidare till en Lambda-funktion eller till en annan server. (AWS: API Gateway HTTP APIs)

I lektion 70 gav API Gateway ditt API en HTTPS-adress. Här ser du vad som händer med anropet när det kommer fram.

Vad händer med anropet?

API Gateway gör fyra saker med varje anrop, här PUT /customers/abc-123: (AWS: Routes for HTTP APIs, AWS: HTTP API och Lambda)

  1. Matchar en route. En route är metod plus sökväg, som i Express.
  2. Gör ett event. Anropet görs om till ett event i JSON, med samma form som testhändelsen.
  3. Anropar funktionen. Lambda kör funktionen, och handlern får eventet.
  4. Gör ett HTTP-svar. Objektet som handlern returnerar blir HTTP-svaret till klienten.

HTTP API eller REST API?

Du bygger ett HTTP API, inte ett REST API. Båda är API-typer i API Gateway, och båda bygger REST-API:er. Namnen är alltså förvirrande. (AWS: Choose between REST APIs and HTTP APIs)

REST API har fler funktioner, som du inte behöver här. HTTP API har färre och kostar under en tredjedel så mycket per anrop. Det räcker för ditt API. I konsolen väljer du HTTP API och klickar Build. (AWS: API Gateway pricing)

Sammanfattning

  • Ett HTTP API är en API-typ i API Gateway som skickar anrop vidare, här till din Lambda-funktion.
  • API Gateway matchar anropet mot en route, gör om det till ett event, anropar funktionen och gör om svaret till HTTP.
  • Du bygger ett HTTP API, inte ett REST API. Båda bygger REST-API:er, men HTTP API är enklare, kostar mindre och räcker här.
