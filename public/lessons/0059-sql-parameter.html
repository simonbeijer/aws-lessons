Lektion 59

SQL-parameter

Vad du ska veta efter lektionen Varför värden skickas som $1 i stället för att klistras in i SQL-strängen, och vad SQL-injektion är.

Vad är en SQL-parameter?

En SQL-parameter är en plats i SQL-frågan, skriven $1, som fylls med ett värde som skickas separat. SQL är språket programmet ställer frågor till databasen med, här PostgreSQL. (PostgreSQL: PREPARE, node-postgres: Parameterized query)

pool.query(
  "SELECT id, name FROM customers WHERE id = $1",
  [id]
);
DelBetyder
pool.querySkickar frågan till databasen. pool är programmets kopplingar dit.
"SELECT ... $1"Frågan, som text (en sträng). SELECT hämtar id och name ur tabellen customers, WHERE väljer raden där id är $1.
[id]En lista med värdena, t.ex. req.params.id. Det första fylls i på $1.

Vad är SQL-injektion?

SQL-injektion är när ett värde klistras in i SQL-strängen och databasen kör delar av det som SQL. Här sätter koden ihop en INSERT, som lägger till en kund, med +: (OWASP: SQL Injection, PostgreSQL: INSERT)

"INSERT INTO customers (name) VALUES ('" + name + "')"

Skickar någon namnet x'); DROP TABLE customers; -- i JSON-kroppen, blir frågan:

INSERT INTO customers (name) VALUES ('x'); DROP TABLE customers; --')

' avslutar texten, ; avslutar kommandot och -- gör resten till en kommentar, text som databasen hoppar över. Kvar blir kommandot DROP TABLE customers, som raderar tabellen. (PostgreSQL: Lexical structure, PostgreSQL: DROP TABLE)

Varför $1 stoppar det

Med $1 skickas frågan och värdet var för sig, så databasen läser värdet som data, aldrig som kod. Samma namn sparas då bara som ett kundnamn. (node-postgres: Parameterized query, OWASP: Parameterized queries)

Kursens poäng: SQL med parametrar, aldrig ihopklistrade strängar. (kursens lektion sida 22)

Sammanfattning

  • En SQL-parameter, $1, är en plats i frågan. Värdet skickas separat i en lista: pool.query("... WHERE id = $1", [id]).
  • SQL-injektion: ett värde klistras in i SQL-strängen, och databasen kör en del av det som SQL, t.ex. DROP TABLE customers.
  • Med $1 läser databasen värdet som data, aldrig som kod. Klistra aldrig ihop SQL-strängar med värden från ett anrop.
