Lektion 110

Throttling

Vad du ska veta efter lektionen Att rate och burst sätter en gräns för hur många anrop per sekund API:et tar emot, och att anrop över gränsen får 429 utan att funktionen körs.

Vad är throttling?

Throttling är en gräns för hur många anrop API Gateway släpper igenom per sekund. Du sätter den på en stage, under Deploy → Stages → $default och sedan Throttling. (AWS: Throttle requests to your HTTP APIs, kursmaterialet v42)

Gränsen gäller alla klienter tillsammans. Ett HTTP API kan inte sätta en gräns per klient. (AWS: REST APIs och HTTP APIs)

Vad är rate och burst?

Rate och burst är gränsens två tal. Varje anrop tar en pollett ur en hink. Är hinken tom, stoppas anropet. (AWS: Throttle requests, token bucket)

  • Burst är hur många polletter hinken rymmer: så många anrop får komma på en gång.
  • Rate är hur många polletter som fylls på per sekund: takten i längden.
Ej exakt

AWS kallar gränsen ett mål. Ibland släpps fler anrop igenom.

Vad händer över gränsen?

API Gateway svarar 429 Too Many Requests, med kroppen {"message":"Too Many Requests"}. Koden börjar på 4, så det räknas som klientens fel. (AWS: Throttle requests to your HTTP APIs)

Funktionen körs inte. Anropet syns därför inte i funktionens logg i CloudWatch Logs. Så skyddar gränsen funktionen, och DynamoDB bakom den, från en klient som skickar för många anrop. I lektion 67 hämtades 184 000 bokningar, utan någon sådan gräns.

Sammanfattning

  • Throttling är en gräns för antal anrop per sekund, satt på en stage. I ett HTTP API gäller den alla klienter tillsammans.
  • Burst är hur många anrop som får komma på en gång. Rate är hur många per sekund som släpps igenom i längden.
  • Anrop över gränsen får 429 Too Many Requests från API Gateway. Funktionen körs inte, så gränsen skyddar den och det bakom den.

Källor

Huvudkälla: Amazon API Gateway: Throttle requests to your HTTP APIs.

Om rate och burst i hinken: Amazon API Gateway: Throttle requests to your REST APIs.
