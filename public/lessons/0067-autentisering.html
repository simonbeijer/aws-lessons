Lektion 67

Autentisering

Vad du ska veta efter lektionen Att autentisering kontrollerar vem som anropar, och att ett anrop utan token ska få 401.

Vad är autentisering?

Autentisering är att servern kontrollerar vem som anropar. Du autentiseras själv när du loggar in i AWS med e-post och lösenord. (MDN: HTTP authentication)

En app skickar inte lösenordet i varje anrop. Den skickar en token: en lång rad tecken som appen fick när användaren loggade in. Den som har token räknas som den användaren. (RFC 6750: Bearer token)

Var står token?

Token står i headern Authorization, efter ordet Bearer. Det betyder att den som bär token ska släppas in: (RFC 6750: Authorization header)

GET /bookings/42 HTTP/1.1
Authorization: Bearer mF_9.B5f-4.1JqM

Servern kontrollerar token först. Saknas den, eller är den ogiltig, svarar servern 401 Unauthorized och hämtar ingenting. (MDN: 401 Unauthorized, kursens lektion sida 27)

401 är en 4xx: klienten ska logga in och skicka anropet igen med token. Trots namnet gäller 401 vem du är, inte vad du får göra. Det senare är nästa lektion. (MDN: 401 Unauthorized)

Varför kontrollera på servern?

Servern måste kontrollera, för vem som helst kan anropa API:et utan appen, till exempel med curl. Bokningsappen i förra lektionen skickade alltid en token. Därför kontrollerade ingen att anrop som /bookings/42 krävde den, och 184 000 bokningar hämtades utan token. (kursens lektion sida 24–25)

401 till alla utan token hade räckt för att stoppa läckan. Därför är första åtgärden att kräva token på servern. (kursens lektion sida 27–28)

Gör så här

Lägg till ett negativt test: samma anrop utan Authorization ska få 401.

Quiz

1. Ett anrop till /bookings/42 saknar token. Vad ska servern svara?

2. Appen skickar alltid en token. Måste servern ändå kontrollera den?

3. Repetition från lektion 50: 401 börjar på 4. Vem ska ändra något?

Sammanfattning

  • Autentisering är att servern kontrollerar vem som anropar. Appen skickar en token som den fick vid inloggningen.
  • Token står i headern Authorization: Bearer .... Saknas den eller är ogiltig svarar servern 401 och hämtar ingenting.
  • Kontrollen måste ligga på servern, för vem som helst kan anropa API:et utan appen.

Källor

Huvudkälla: MDN: 401 Unauthorized.

Om token i headern: RFC 6750: Bearer token. Översikt: MDN: HTTP authentication.
