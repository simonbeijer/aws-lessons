Lektion 63

Negativt test

Vad du ska veta efter lektionen Varför testerna i Postman också kontrollerar att felaktiga anrop ger 400 och 404.

Vad är ett negativt test?

Ett negativt test skickar ett anrop som ska misslyckas och kontrollerar att svaret har rätt felkod. Testet blir grönt när API:et svarar 400 eller 404, som det ska. (kursmaterialet v41)

Testerna i förra lektionen prövar den lyckliga vägen: rätta anrop som ska ge 200, 201 eller 204. (kursmaterialet v41)

Tre fel som kursen testar

Kursen har tre negativa tester, och varje fel har sin statuskod: (kursmaterialet v41, MDN: 400 Bad Request, MDN: 404 Not Found)

AnropVäntad kodVarför
GET /customers/42 när kund 42 är borttagen404Kunden finns inte.
POST /customers med {"name":""}400Namnet är tomt.
GET /customers/abc400abc kan aldrig vara ett kundnummer.

Testet skrivs som i förra lektionen. Bara siffran är en annan: (kursmaterialet v41, Postman: Test for a status code)

pm.test("Status 404", () => pm.response.to.have.status(404));

Varför felen också testas

Ett API som bara testas på den lyckliga vägen går sönder i det som inte testades. Därför är de negativa testerna enligt kursen de viktigaste. (kursmaterialet v41)

Ett exempel: DELETE svarar 204 men tar inte bort kunden ur databasen. Alla tester på den lyckliga vägen blir gröna. Bara hämtningen efteråt avslöjar felet, med 200 i stället för 404. (kursmaterialet v41)

Felkoden är också ett besked till klienten: 400 betyder att anropet ska ändras, 404 att resursen inte finns. (lektion 50, MDN: Client error responses)

Sammanfattning

  • Ett negativt test skickar ett anrop som ska misslyckas och kontrollerar att felkoden är rätt, t.ex. 400 eller 404.
  • Kursens tre: borttagen kund ger 404, tomt namn ger 400, /customers/abc ger 400. Testet är samma rad som förut, med en annan siffra.
  • Ett API som bara testas på den lyckliga vägen går sönder i det som inte testades. Felkoden är dessutom ett besked till klienten.
