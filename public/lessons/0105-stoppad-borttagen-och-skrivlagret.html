Vad händer när containern stoppas eller tas bort?

Kort sagt En stoppad container finns kvar, en borttagen gör det inte. Det du ändrat inne i den försvinner med den, men imagen den kom från ändras aldrig. Det avgör var data som ska sparas måste ligga när API:et och databasen körs i containrar.

Stoppad eller borttagen?

docker stop web stoppar programmet i containern, men containern finns kvar. docker ps visar bara körande containrar, så den syns inte där. docker ps -a (all) visar även stoppade, med status Exited. docker start web startar den igen.

docker rm web tar bort containern helt. Vill du ta bort en som fortfarande kör behövs -f (force), som tvingar bort den.

Var hamnar ändringarna?

Imagen är en skrivskyddad mall. Containern får därför ett eget skrivbart lager ovanpå, skrivlagret. Allt som ändras i containern skrivs dit, nya filer såväl som ändrade, till exempel med docker exec. Lagret hör till just den containern.

Efter stop ligger lagret kvar, så efter start finns ändringen där. rm tar bort lagret med containern. Imagen är orörd, så en ny container från samma image börjar utan ändringen.

Vad överlever?

Eftersom skrivlagret försvinner med containern ska en container gå att slänga och ersätta med en ny från samma image. Det som ska överleva måste därför ligga utanför den: i en databas, i S3 (Simple Storage Service) eller i en volym, som förklaras senare i veckan.

Ska containern ändå slängas kan Docker göra det åt dig. docker run --rm tar bort containern automatiskt när den avslutas, så ingen Exited-container blir kvar efter en körning du bara ville göra en gång.

Quiz

1. Du har kört docker stop web. Var finns containern?

2. Du ändrar en fil i web, tar bort containern med docker rm och startar en ny från samma image. Vad ser du?

3. Du kör en container med --rm och den avslutas. Vad visar docker ps -a om den?

Sammanfattning

  • docker stop behåller containern: den syns i docker ps -a som Exited, inte i docker ps. docker start startar den igen. docker rm tar bort den, rm -f även en som kör.
  • Ändringar i containern ligger i dess skrivlager. Det försvinner med rm, och imagen ändras aldrig.
  • --rm tar bort containern när den avslutas. Det som ska överleva måste ligga utanför containern.

Källor

Huvudkälla: Docker: Storage drivers. Att data i containerlagret inte finns kvar när containern förstörs: Docker: Storage. docker ps -a: Docker: docker container ls. rm och -f: Docker: docker container rm. --rm: Docker: docker container run. Att docker ps bara visar körande containrar, att en stoppad får status Exited och att -f tvingar bort en körande container står i referenserna ovan. Att skrivlagret ligger kvar efter stop och att ändringen finns kvar efter start står inte uttryckligen i Docker-dokumentationen, som bara beskriver att lagret tas bort med containern. Det kommer från kursen.
