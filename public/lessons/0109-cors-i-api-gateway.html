Lektion 109

CORS i API Gateway

Vad du ska veta efter lektionen Att API Gateway svarar på CORS själv, med tillåtna ursprung, headers och metoder, utan att funktionen körs. Inställningen ligger i API Gateway, inte i koden.

Var ställs CORS in?

CORS ställs in i ditt HTTP API, under Develop → CORS i konsolen. Där fyller du i tre listor, ett värde i taget med Add. (AWS: Configure CORS for HTTP APIs, kursmaterialet v42)

ListaExempel
Access-Control-Allow-Originhttp://localhost:5173
Access-Control-Allow-Headerscontent-type
Access-Control-Allow-MethodsGET, POST, PUT, DELETE

I lektion 69 skickade servern headern från sin egen kod. Här skickar API Gateway den, och funktionens kod behöver inte veta något om CORS.

Vem svarar på preflight?

API Gateway svarar själv på preflight, även om API:et inte har någon route för OPTIONS. Svaret innehåller listorna ovan. (AWS: Configure CORS for HTTP APIs)

Funktionen körs inte. Lambda tar betalt per anrop, så preflight blir inget Lambda-anrop att betala för.

Vad händer med vanliga svar?

Vid GET och POST körs funktionen som vanligt. API Gateway lägger sedan till CORS-headers på funktionens svar. Skickar funktionen egna CORS-headers, struntar API Gateway i dem. (AWS: Configure CORS for HTTP APIs)

Står sidans ursprung inte i listan, saknas Access-Control-Allow-Origin i svaret, och webbläsaren blockerar det. Ursprunget måste stavas exakt: rätt schema och inget / sist.

Gör så här

Lista exakt de ursprung som ska få läsa, inte *.

Ursprunget står i listan. Preflight får 204, med headern:

access-control-allow-origin: http://localhost:5173

Fungerar Webbläsaren skickar POST:en.

Ursprunget står inte i listan. Svaret saknar access-control-allow-origin.

Stoppad Webbläsaren på den sidan skickar aldrig POST:en.

Quiz

1. Din sida på Amplify får CORS-fel mot ditt HTTP API. Var lägger du till sidans adress?

2. CORS är inställt, och webbläsaren skickar preflight till /customers. Vad händer?

3. Repetition från lektion 69: listan har http://localhost:3000, men sidan körs på http://localhost:5173. Får koden läsa svaret?

Sammanfattning

  • CORS för ett HTTP API ställs in i API Gateway, under Develop → CORS, med listor för tillåtna ursprung, headers och metoder. Funktionens kod vet inget om det.
  • API Gateway svarar själv på preflight, även utan en OPTIONS-route. Funktionen körs inte, så det blir inget Lambda-anrop.
  • På vanliga svar lägger API Gateway till CORS-headers och struntar i funktionens egna. Ursprunget måste stå exakt rätt i listan, annars blockerar webbläsaren svaret.
