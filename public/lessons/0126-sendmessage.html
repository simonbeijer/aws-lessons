Lektion 126

SendMessage

Vad du ska veta efter lektionen Att SendMessageCommand med QueueUrl och MessageBody lägger ett meddelande på kön, och att rollen bara får sqs:SendMessage på den kön.

Vad gör SendMessage?

SendMessage lägger ett meddelande på den kö som QueueUrl pekar ut (lektion 125). Producenten anropar den med AWS SDK. MessageBody är en sträng, så ett objekt görs om med JSON.stringify som i lektion 98. Ett lyckat anrop svarar med meddelandets message ID. (AWS: SendMessage, AWS: SendMessage med SDK for JavaScript)

import { SQSClient, SendMessageCommand } from "@aws-sdk/client-sqs";

const client = new SQSClient({});
const queueUrl = process.env.QUEUE_URL;

await client.send(new SendMessageCommand({
  QueueUrl: queueUrl,
  MessageBody: JSON.stringify({ id: 7 })
}));

queueUrl läses från miljövariabeln QUEUE_URL, precis som TABLE_NAME i lektion 94. Då kan samma kod skicka till en annan kö i en annan miljö.

Vad får rollen göra?

Funktionens execution role får bara sqs:SendMessage på en enda kö, med köns ARN som resurs (lektion 125). Det är minsta möjliga behörighet: en handling på en resurs. (AWS: SQS API permissions)

{
  "Effect": "Allow",
  "Action": "sqs:SendMessage",
  "Resource": "arn:aws:sqs:eu-north-1:123456789012:v43-customer-events"
}

Sammanfattning

  • SendMessageCommand med QueueUrl och MessageBody lägger ett meddelande på kön, och svaret har message ID.
  • Kroppen är en sträng, så objekt går genom JSON.stringify.
  • Rollen får bara sqs:SendMessage på en kö, med köns ARN.
