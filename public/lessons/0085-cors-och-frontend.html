Hur anropar webbsidan API:et?

Kort sagt Webbsidan på Amplify ska anropa API:et (Application Programming Interface) på adressen från förra lektionen. Det kräver två saker: sidan måste få adressen, och webbläsaren måste få ett ja från API:et innan den skickar något.

Hur får sidan adressen?

Adressen är API:ets Invoke URL (Uniform Resource Locator) från förra lektionen. Sidan får den som en miljövariabel. I Vite (verktyget som bygger sidan) heter den VITE_API_URL. Koden läser den med import.meta.env.VITE_API_URL.

Lokalt står värdet i .env.local, som inte checkas in, så Amplify får ett eget. Vid bygget byter Vite ut uttrycket mot adressen i JavaScript-koden, så ett nytt värde gäller först efter nästa bygge.

Varning

Adressen står i koden som varje besökare hämtar. Lägg aldrig ett lösenord eller en nyckel i en VITE_-variabel.

Varför frågar webbläsaren först?

Sidan på Amplify och API:et har olika ursprung, så CORS (Cross-Origin Resource Sharing) gäller.

En POST med JSON (JavaScript Object Notation) skickas inte direkt, för application/json är inget av de Content-Type-värden som slipper kontroll. Webbläsaren skickar först ett preflight, ett OPTIONS-anrop (HTTP-metod). Det anger sidans ursprung (Origin), metoden och headers som POST:en använder, och frågar om det är tillåtet. Tillåter svaret det, skickas POST:en. Annars skickas den aldrig.

I Network-fliken syns två rader: OPTIONS med status 204, sedan POST med 201.

Vem svarar på frågan?

API Gateway, inte funktionen. Det gäller även utan route för OPTIONS. API:ets CORS-inställning har tre listor: Access-Control-Allow-Origin, Access-Control-Allow-Headers (content-type) och Access-Control-Allow-Methods (till exempel GET, POST).

Ursprunget stavas exakt, utan / sist. Sidan har två ursprung: http://localhost:5173 lokalt och sin Amplify-adress. Båda ska stå med.

Nästa vecka lämnar API:et jobbet vidare till en kö.

Quiz

1. Du byter värdet på VITE_API_URL i Amplify. Sidan anropar fortfarande den gamla adressen. Varför?

2. Network-fliken visar en OPTIONS-rad och ingen POST-rad. Vad har hänt?

3. CORS-listan har http://localhost:5173/ med snedstreck sist. Sidan på localhost kör POST med JSON. Vad händer?

Sammanfattning

  • VITE_API_URL står i .env.local lokalt och i Amplify. Vite byter in värdet i JavaScript vid bygget, så adressen syns för alla. Inga hemligheter i VITE_-variabler.
  • En POST med application/json får först ett OPTIONS-anrop (preflight). Tillåts den, skickas POST:en, annars aldrig.
  • API Gateway svarar på preflight utan att funktionen körs. CORS-listorna: Allow-Origin, Allow-Headers, Allow-Methods. Ursprung stavas exakt.
