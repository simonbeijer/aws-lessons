Veckan i överblick: bygg och testa ett API

Vad du ska veta efter lektionen Vad veckans API blir och var varje begrepp passar in.

Vad bygger vi?

Ett REST-API (Representational State Transfer, Application Programming Interface) i Express på din EC2-server. Det svarar med JSON (JavaScript Object Notation) ur databasen RDS och nås från din dator på port 3000.

Vad liknar det?

En Express-server på din Mac på localhost:3000. Samma kod, samma curl och Postman, samma statuskoder.

Det håller inte här: EC2 har en egen publik adress bakom en security group, och databasen når du bara via webbservern. En sida på HTTPS (HTTP Secure) får inte heller anropa HTTP (Hypertext Transfer Protocol), vilket lokalt aldrig händer.

Veckans begrepp

  1. HTTP-anrop och svar: det som går mellan pilarna
  2. HTTP-metod: säger vad anropet gör
  3. Statuskod: hur det gick
  4. Header: extra uppgifter i anropet
  5. JSON: formen på svaret
  6. REST-API: hur anropen formas
  7. curl: anropa från terminalen
  8. Postman: anropa med ett program
  9. Network-fliken: se webbläsarens anrop
  10. Express: servern på EC2
  11. localhost: din egen dator
  12. SQL-parameter: SQL (Structured Query Language), värden till databasen
  13. Process i bakgrunden: servern lever kvar
  14. Variabel i Postman: adressen på ett ställe
  15. Test i Postman: kontrollerar svaret
  16. Negativt test: kontrollerar felen
  17. YAML: YAML Ain't Markup Language, formatet OpenAPI-filen skrivs i
  18. OpenAPI: API:et beskrivet i en fil
  19. Swagger UI: prova anrop på en sida
  20. Autentisering: vem anropar
  21. Ägarkontroll: vems objekt det är
  22. CORS (Cross-Origin Resource Sharing): webbläsarens spärr mellan Amplify och EC2
  23. Mixed content: HTTPS-sida mot HTTP-server

Efter veckan

Du kan anropa API:et med curl, Postman och Swagger UI, läsa statuskoderna, och förklara varför databasen och webbservern nås olika.
