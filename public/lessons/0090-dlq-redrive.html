Hur får man tillbaka ett trasigt meddelande?

Kort sagt Meddelandena i dödbrevskön väntar där på att någon ska rätta felet. DLQ redrive (dead-letter queue redrive) skickar tillbaka dem till huvudkön så att de får nya försök.

Vad gör redrive?

När felet är rättat flyttar DLQ redrive meddelandena från dödbrevskön tillbaka till källkön, huvudkön de kom från. Konsolens knapp Start DLQ redrive finns på dödbrevskön, inte på huvudkön. Låg ett meddelande i dödbrevskön står det efteråt 1 i huvudkön och 0 i dödbrevskön.

SQS (Simple Queue Service) ändrar inte innehållet, men det som läggs i huvudkön är en ny kopia. Den får ett nytt message ID, och retention-tiden börjar om, till skillnad från flytten till dödbrevskön som behöll klockan. Receive count börjar också om från 0, så med Maximum receives 3 får meddelandet tre nya försök.

Inte bekräftat av AWS Att receive count börjar om från 0 står i kursen, inte i AWS dokumentation.

Quiz

1. Vad är ett meddelande efter redrive, jämfört med innan?

2. Ett meddelande låg 3 dagar i huvudkön och flyttades till dödbrevskön. Sedan görs redrive. Hur räknas retention i huvudkön?

Sammanfattning

  • Start DLQ redrive finns på dödbrevskön och flyttar meddelandena tillbaka till källkön, utan att ändra dem.
  • De kommer som en ny kopia: nytt message ID, retention börjar om, receive count från 0 (receive count enligt kursen).

Källor

Huvudkälla: AWS: DLQ redrive. Dessutom StartMessageMoveTask. Ett blogginlägg från AWS säger att message ID behålls, men Developer Guide säger nytt, och den följs här.
