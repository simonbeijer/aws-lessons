Vad får handlern in och vad ska den svara?

Kort sagt Nu når anropet funktionen, men handlern från lektion 81 returnerar ingenting som en klient kan använda. API Gateway skickar anropet som ett event med fasta platser, och väntar sig ett svar i en bestämd form.

Var står uppgifterna?

API Gateway packar hela HTTP-anropet (Hypertext Transfer Protocol) i ett event. Fyra delar behövs, här för PUT /customers/abc-123:

DelI kodenVärde
Metodenevent.requestContext.http.method"PUT"
Sökvägenevent.rawPath"/customers/abc-123"
Id:tevent.pathParameters.id"abc-123"
Kroppenevent.body"{\"name\":\"Carol\"}"

Som testhändelse räcker:

{
  "rawPath": "/customers/abc-123",
  "requestContext": { "http": { "method": "PUT" } },
  "pathParameters": { "id": "abc-123" },
  "body": "{\"name\":\"Carol\"}"
}

body är en sträng, inte ett objekt. Kroppen inuti är JSON (JavaScript Object Notation) med egna citattecken, så ett vanligt " avslutar strängen för tidigt. Därför skrivs de \". Koden gör om strängen till ett objekt med JSON.parse(event.body).

Hur ser svaret ut?

Handlern returnerar ett objekt med tre delar, och API Gateway gör HTTP-svaret av det. statusCode blir statuskoden, headers blir headers och body kroppen.

return {
  statusCode: 404,
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ error: "customer 999 not found" })
};

Också body är en sträng. JSON.stringify gör om ett objekt till text, motsatsen till JSON.parse. I Express skrev res.status(404).json(...) svaret. Här returnerar handlern det.

Vad händer vid fel?

Kastar koden ett fel som inget try/catch fångar, finns inget svar att lämna. Klienten får då ett 5xx-fel och bara {"message":"Internal Server Error"}. Detaljerna står i CloudWatch Logs. Fångar du felet kan du returnera ett eget svar, till exempel 404.

Till skillnad från 404:an i förra lektionen körs funktionen här, men kraschar.

Nästa lektion handlar om adressen klienten anropar och om vem som får anropa funktionen.

Sammanfattning

  • Metoden står i event.requestContext.http.method, sökvägen i event.rawPath, id:t i event.pathParameters.id och kroppen i event.body.
  • body är en sträng. Citattecknen inuti skrivs \", och JSON.parse gör om den till ett objekt.
  • Svaret är ett objekt med statusCode, headers och body. body är en sträng, gjord med JSON.stringify.
  • Ett fel som inte fångas ger klienten ett 5xx-fel och bara Internal Server Error. Detaljerna står i CloudWatch Logs.

Källor

Huvudkälla: Amazon API Gateway: Lambda proxy integrations for HTTP APIs.

Om fel: HTTP API Internal Server Error och Handling Lambda errors with an API Gateway API. Kursen säger 500 för ett ofångat fel. AWS felsida för Lambda säger 502 och API Gateways egen sida anger ingen kod, så exakt kod är obekräftad. Därför står det 5xx här.

Om escapade citattecken: RFC 8259: Strings. Om JSON.parse och JSON.stringify: MDN: JSON.parse(), MDN: JSON.stringify().
