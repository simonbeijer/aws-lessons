Hur skickar API:et en händelse?

Kort sagt Regeln och målen står klara (förra lektionen). Nu ska API:et skicka händelsen, med PutEvents i stället för SendMessage. Händelsen kommer fram till kön inlindad i ett kuvert, och därför läser konsumenten den på ett nytt sätt.

Vad skickar anropet?

API:et (Application Programming Interface) byter SendMessage (lektion 91) mot PutEventsCommand i AWS SDK (Software Development Kit). Anropet tar Entries, en lista med poster med tre fält var:

Entries: [{
  Source: "kundregister",
  DetailType: "CustomerCreated",
  Detail: JSON.stringify({ id, name }),
}]

Source och DetailType är det regeln matchar på (lektion 98). Detail är innehållet, en sträng med JSON (JavaScript Object Notation) precis som MessageBody, och JSON.stringify gör objektet till den. Utan EventBusName går händelsen till bussen default.

Rollen måste tillåta events:PutEvents på bussens ARN (Amazon Resource Name), annars blir det AccessDeniedException.

Kom den in?

En post kan misslyckas, till exempel om ett fält saknas, men anropet svarar ändå 200. FailedEntryCount i svaret är antalet poster som inte kom in. Är det över 0 måste koden kasta eller skicka om.

Vad får konsumenten?

Ett mål får hela händelsen, inte bara Detail. Den ligger i ett kuvert, med innehållet i fältet detail:

{
  "id": "a1b2…",
  "detail-type": "CustomerCreated",
  "source": "kundregister",
  "time": "2026-10-22T15:10:00Z",
  "region": "eu-north-1",
  "detail": { "id": "9b1d…", "name": "Alice" }
}

Runt detail lägger EventBridge bland annat id, som identifierar händelsen, och time, när den hände. Kön får kuvertet som body, så efter JSON.parse (lektion 94) ligger det API:et skickade i body.detail.

Därför läser konsumenten body.detail ?? body. Operatorn ?? tar vänstra värdet om det finns, annars det högra: detail via bussen, body direkt från kön. Utan raden blir kundens id undefined, och DynamoDB svarar ValidationException.

Quiz

1. PutEvents svarar 200 utan fel, men FailedEntryCount är 1. Vad betyder det?

2. Vad skickas som en sträng i en post?

3. Konsumenten läser body.detail ?? body. Vad ligger i body.detail när händelsen kom via bussen?

Sammanfattning

  • PutEventsCommand skickar Entries. Varje post har Source, DetailType och Detail som sträng.
  • 200 betyder inte att allt kom in. FailedEntryCount visar det som inte gjorde det.
  • EventBridge lägger ett kuvert runt detail, så konsumenten läser body.detail ?? body.

Källor

Huvudkällor: AWS: PutEvents, AWS: PutEventsRequestEntry och AWS: Event structure. Behörigheten: AWS: Actions, resources and condition keys for Amazon EventBridge (PutEvents gäller resurstypen event-bus). Att ett mål får hela händelsen när inget Input, InputPath eller InputTransformer är satt: AWS: PutTargets. Att en saknad body.detail ?? body ger ValidationException står i kursmaterialet. Kursmaterialet säger också att FailedEntryCount blir 1 när bussen inte finns. AWS säger att anropet då ger 200 och inte räknas som misslyckat, och här gäller AWS.
