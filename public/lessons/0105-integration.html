Lektion 105

Integration

Vad du ska veta efter lektionen Att integrationen är det som står bakom en route, här funktionen v42-api, och att den kan bytas utan att adressen ändras.

Vad är en integration?

En integration är det som en route skickar anropet till. I ditt API är det funktionen v42-api. När en route matchar anropar API Gateway integrationen, och svaret går tillbaka till klienten. (AWS: Integrations for HTTP APIs)

Du väljer integrationen när du skapar API:et, under Add integration: Lambda, region eu-north-1, funktionen v42-api. Alla fem routes har samma integration. I konsolen ser du den under Integrations. (AWS: CRUD API tutorial)

Vad kan stå bakom?

Bakom en route kan det också stå en server. I lektion 70 skickade API Gateway anropet till ditt API på EC2. Då är integrationen serverns HTTP-adress, inte en funktion. (AWS: HTTP proxy integrations)

Det kan också vara en Application Load Balancer inne i ditt VPC, med servrar bakom. (AWS: Private integrations)

Vad händer med adressen?

Adressen ändras inte när du byter integration. Klienten anropar API:ets adress, inte funktionen. Funktionens namn finns inte i adressen. (AWS: API:ets adress)

Adressen och dina routes är ingången. Integrationen är det som står bakom. Byter du det som står bakom, anropar sidan på Amplify samma adress.

Samma adress GET /customers går till Lambda, som kör v42-api.

Samma adress GET /customers går till serverns HTTP-adress.

Samma adress GET /customers går till load balancern, som väljer en server.

Sammanfattning

  • En integration är det som en route skickar anropet till. I ditt API är det funktionen v42-api, för alla fem routes.
  • Bakom en route kan det också stå en server, eller en Application Load Balancer med servrar bakom.
  • Adressen hör till API:et, inte till integrationen. Byter du integration anropar klienten samma adress som förut.
