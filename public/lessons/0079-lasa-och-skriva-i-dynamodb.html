Hur läser och skriver man i DynamoDB?

Kort sagt Kunderna ligger i en tabell, men funktionen måste kunna hämta, spara, ändra och ta bort dem. Varje sådan åtgärd är en operation med eget namn. Att ändra en kund är knepigast: den som ändrar en kund som inte finns skapar i stället en ny.

Vilka operationer finns?

Du pratar med DynamoDB genom operationer, ett anrop per sak. Fyra gäller ett enda item, som du pekar ut med id. Den femte, Scan, gäller alla.

OperationGör
GetItemHämtar itemet med ett visst id.
PutItemSparar ett helt item. Samma id ersätter det gamla.
UpdateItemÄndrar enskilda attribut i ett item.
DeleteItemTar bort itemet med ett visst id.
ScanLäser varje item i tabellen.

Scan tar inget id, så den måste gå igenom allt. Med on-demand betalar du per läsning, och en Scan läser varje item. Därför kostar den mer ju större tabellen är.

Hur ändrar man ett attribut?

PutItem skriver över hela itemet. Vill du bara byta namn på en kund tar du UpdateItem, som vill ha ett uttryck (expression): en kort text som säger vad som ska ändras. SET ger ett attribut ett nytt värde. Anropet ser ut så här, med Key som pekar ut itemet i tabellen v42-customers:

{
  TableName: "v42-customers",
  Key: { id: "demo-1" },
  UpdateExpression: "SET #n = :n",
  ExpressionAttributeNames:  { "#n": "name" },
  ExpressionAttributeValues: { ":n": "Carol" }
}

#n och :n är platshållare. # först betyder alias, ett ersättningsnamn för ett attribut, och : först betyder värde. ExpressionAttributeNames säger att #n är attributet name, och ExpressionAttributeValues att :n är Carol.

Varför inte skriva SET name = :n? Eftersom name är ett reserverat ord. DynamoDB använder ordet själv, så det får inte stå i ett uttryck. Flera hundra ord är reserverade, som status och date. Attributet heter fortfarande name i itemet. Utan alias stoppas anropet:

ValidationException: Invalid UpdateExpression:
Attribute name is a reserved keyword

Vad om itemet inte finns?

UpdateItem skapar det. Ändrar du kunden finns-inte blir det ett nytt item med bara id och name. DeleteItem är lika tyst: tar du bort ett item som inte finns blir det inget fel, och koden skulle svara som om kunden togs bort.

Lösningen är ett villkor i ConditionExpression. Det måste vara sant, annars görs ingenting och anropet kastar ett fel. Villkoret attribute_exists(id) är sant bara om itemet har attributet id. Varje item har det, så villkoret betyder att itemet måste finnas.

ConditionExpression: "attribute_exists(id)"

Felet heter ConditionalCheckFailedException. Koden fångar det och svarar med statuskoden 404 (Not Found), att kunden inte finns. Andra fel fångas inte och blir 5xx. Samma villkor och samma 404 gäller DeleteItem.

Quiz

1. Funktionen ska visa alla kunder i tabellen. Vilken operation passar?

2. I SET #n = :n finns två platshållare. Vad är de?

3. Du ändrar en kund med ett id som inte finns, utan något villkor. Vad händer?

4. Repetition: PutItem sparar ett item med ett id som redan finns. Vad blir resultatet?

Sammanfattning

  • GetItem, PutItem, UpdateItem och DeleteItem gäller ett item med ett visst id. Scan läser hela tabellen och kostar mer ju större den är.
  • I SET #n = :n är #n ett alias för ett attributnamn och :n ett värde. ExpressionAttributeNames och ExpressionAttributeValues säger vad de står för.
  • name är ett reserverat ord, liksom status och date, och måste ha ett alias i uttryck.
  • UpdateItem skapar ett item som inte finns, och DeleteItem ger inget fel. attribute_exists(id) i ConditionExpression stoppar båda. Felet ConditionalCheckFailedException görs om till 404.
