Måste allt byggas om?

Kort sagt Första bygget installerar alla paket. En image byggs dock i lager, och Docker återanvänder de som inte ändrats. Därför går ombygget snabbt efter en liten kodändring, så länge raderna i Dockerfilen ligger i rätt ordning.

Vad är ett lager?

Du ändrar en rad i server.js och bygger imagen igen. Ska alla paket installeras på nytt? Nej: imagen byggs i lager.

Varje rad i Dockerfilen som ändrar filer blir ett lager, ett steg som lägger filer ovanpå de tidigare. docker image history kundregister-api:1 visar ett lager per rad, med kommandot och storleken. COPY package*.json, RUN npm ci och COPY . . har storlek (paketen cirka 21 MB, koden 45 kB). USER, EXPOSE och CMD visar 0 B, eftersom de bara ändrar metadata. Det här är imagens lager, inte containerns skrivlager.

Vad återanvänds?

Docker sparar lagren från förra bygget i byggcachen och jämför varje rad med dem. En RUN är densamma om kommandot är det, en COPY om filerna har samma innehåll. Är raden oförändrad återanvänds lagret, och utskriften säger CACHED. Ändras en rad byggs den om, och allt efter den också.

Vad byggs om i Dockerfilen från lektion 108?

FROM, WORKDIRCACHED
COPY package*.jsonCACHED
RUN npm ciCACHED
COPY . .byggs om
FROM, WORKDIRCACHED
COPY package*.jsonbyggs om
RUN npm cibyggs om
COPY . .byggs om

Varför paketfilerna först?

Koden ändras ofta, paketen sällan. Därför kopieras och installeras paketen före resten av koden. Ändras bara server.js är allt före COPY . . oförändrat, och npm ci slipper köras. Hade COPY . . stått först hade varje kodändring ändrat det lagret och installerat alla paket igen.

Bygger du om med samma tagg flyttas taggen till den nya imagen. En tagg är en pekare, inte en kopia, så den gamla imagen blir kvar utan namn och visas som <none> i docker image ls. docker image prune tar bort de namnlösa.

Quiz

1. Du ändrar bara server.js och bygger om. Vad byggs om?

2. Varför kopieras package*.json och paketen installeras före COPY . .?

3. Du bygger om kundregister-api:1 med samma tagg. Vad händer med den gamla imagen?

Sammanfattning

  • Varje rad som ändrar filer blir ett lager. docker image history visar dem, och USER, EXPOSE och CMD är 0 B.
  • Oförändrade rader återanvänds (CACHED). Första ändrade raden och allt efter den byggs om.
  • Paketfilerna kopieras före koden, så att npm ci inte körs vid varje kodändring.
  • Taggen flyttas till nya imagen, och den gamla blir <none> tills docker image prune.

Källor

Huvudkälla: Docker: Build cache invalidation (jämförelsen per rad, ombyggnad av allt efter första ändrade lagret). CACHED i byggutskriften: Docker: Using the build cache. Lager och att varje rad blir ett lager: Docker: Build cache och Docker: Layers. docker image history visar kolumnerna CREATED BY och SIZE, med 0B för en CMD. Taggen som pekare: docker image tag. <none>: docker image ls. Rensning: docker image prune.

Det här kommer från kursen, inte från Docker-dokumentationen: att USER och EXPOSE också visar 0 B, och storlekarna (paketen cirka 21 MB, koden 45 kB).
