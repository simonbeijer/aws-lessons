Vad händer om skickandet felar?

Kort sagt Förra lektionen lät API:et (Application Programming Interface) skicka ett meddelande när kunden sparats. Då skriver det till två ställen, tabellen och kön. Den andra skrivningen kan misslyckas fast den första lyckades, och då finns kunden utan meddelande.

Två skrivningar, två system

Meddelandet säger att kunden finns, så API:et sparar kunden först, skickar sedan och svarar sist. Skickas först och sparningen felar, får en konsument veta om en kund som inte finns.

await db.send(new PutCommand({ ... }));           // 1. spara kunden
await sqs.send(new SendMessageCommand({ ... }));  // 2. skicka meddelandet
return json(201, customer);                       // 3. svara

Det är två skrivningar till två system, och ingen kan ångra den andra. Felar steg 2, till exempel för att rollen saknar sqs:SendMessage, ligger kunden kvar utan meddelande. Klienten får då 500 Internal Server Error, och loggen visar AccessDeniedException. Skickar klienten om finns kunden två gånger. Felet är ovanligt och syns i loggen, så API:et lever med det.

Quiz

1. SendMessage felar efter att kunden sparats. Vad gäller?

2. Klienten får ett 5xx-fel och skickar om anropet. Vad blir resultatet?

Sammanfattning

  • API:et sparar kunden före SendMessage och svarar sist.
  • Det är två skrivningar till två system. Felar den andra finns kunden kvar utan meddelande, och klienten får ett 5xx-fel.
  • Skickar klienten om finns kunden två gånger.

Källor

Huvudkälla: AWS: Transactional outbox pattern, som kallar det här dual write.
