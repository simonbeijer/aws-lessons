Hur sparar koden en kund?

Kort sagt Funktionen har nu rätt att skriva i tabellen, men ännu ingen kod som gör det. Koden pratar med DynamoDB genom ett färdigt bibliotek från AWS, och ett par rader före handlern förbereder anropen.

Vad består koden av?

import { DynamoDBClient } from "@aws-sdk/client-dynamodb";
import { DynamoDBDocumentClient, PutCommand } from "@aws-sdk/lib-dynamodb";
import { randomUUID } from "node:crypto";

const db = DynamoDBDocumentClient.from(new DynamoDBClient({}));
const TABLE = process.env.TABLE_NAME;

export const handler = async (event) => {
  const kund = { id: randomUUID(), name: "Carol" };
  await db.send(new PutCommand({ TableName: TABLE, Item: kund }));
};

Biblioteket heter AWS SDK (software development kit) och finns redan i Lambda, så ingen npm install behövs. En klient skickar anropen till DynamoDB, och ett kommando säger vad som ska göras. PutCommand är PutItem från lektion 79.

DynamoDB vill ha en typ runt varje värde, som { "S": "Carol" } för text. DynamoDBDocumentClient lägger på typerna, så du skickar ett vanligt objekt.

Varför ligger två rader utanför handlern?

Klienten och TABLE skapas utanför handlern. Den delen körs bara när en ny exekveringsmiljö startar, och miljön sparas mellan anrop (lektion 77). I handlern skapas den om vid varje anrop, och varje anrop blir långsammare.

TABLE_NAME är en miljövariabel. Du sätter den i funktionens konfiguration, och process.env läser den. Då kan samma kod köra mot en annan tabell.

Vilket id får kunden?

DynamoDB delar inte ut löpnummer, så koden skapar id:t själv med randomUUID(). UUID (Universally Unique Identifier) är ett slumpat id som 9b801085-b120-4eba-b9ed-5b7841385dd4. Ett löpnummer går att gissa, ett UUID inte. Ägarkontrollen behövs ändå, för ett id kan läcka.

Än så länge körs koden bara inifrån AWS. Nästa lektion ger den en väg in utifrån.

Sammanfattning

  • AWS SDK finns redan i Lambda. Koden skapar en klient, skickar kommandon med send och använder DynamoDBDocumentClient för vanliga objekt.
  • Klienten och process.env.TABLE_NAME läses utanför handlern: en gång per miljö.
  • Id:t är randomUUID() ur node:crypto, skapat av koden.

Källor

Huvudkälla: AWS Lambda: Using the SDK for JavaScript v3 in your handler.

Om klienten: DynamoDB document client, Using global state och Lambda environment variables. Om id:t: crypto.randomUUID() och RFC 9562.
