Lektion 99

UUID

Vad du ska veta efter lektionen Att id:t för en ny kund blir ett slumpat UUID från randomUUID() i stället för ett löpnummer, och varför ingen kan räkna sig fram till andras id.

Vad är ett UUID?

Ett UUID är ett id på 32 tecken, bara 0–9 och a–f, i fem grupper med bindestreck. Grupperna har 8, 4, 4, 4 och 12 tecken. (RFC 9562: UUID Format)

9b801085-b120-4eba-b9ed-5b7841385dd4

I version 4 slumpas nästan alla tecken. Siffran 4 först i tredje gruppen visar versionen. (RFC 9562: UUID Version 4)

Hur skapas id:t?

Det skapas med randomUUID(), som ger ett nytt UUID version 4 som sträng vid varje anrop. Slumpen kommer från en kryptografisk slumpgenerator, som är gjord för att inte gå att förutse. (Node.js: crypto.randomUUID())

import { randomUUID } from "node:crypto";

const kund = { id: randomUUID(), name: "Carol" };

node:crypto är en modul som finns inbyggd i Node.js, så ingen npm install behövs. import hämtar funktionen, som i lektion 95. Koden skapar alltså id:t själv, inte databasen. (Node.js: Built-in modules)

Varför inte löpnummer?

Ett löpnummer går att räkna fram. I lektion 68 var id:n 1, 2, 3 i tur och ordning. Den som ser sitt id 42 kan prova 43. Ett UUID har ingen ordning. Nästa id säger inget om förra, och det finns ungefär 5 × 1036 möjliga. Att prova id efter id hittar i praktiken inget. (RFC 9562: UUID Version 4, OWASP: Broken Object Level Authorization)

/customers/42  ditt
/customers/43  nästa kund
/customers/9b801085-b120-4eba-b9ed-5b7841385dd4  ditt
/customers/???  går inte att räkna fram

UUID stoppar att någon hämtar allt genom att räkna. Ägarkontrollen behövs ändå, för ett id kan läcka, till exempel i en länk. (RFC 9562: Security Considerations)

Quiz

1. Ett API ger kunderna id 41, 42 och 43 i tur och ordning. Vad är problemet?

2. Vad ger randomUUID()?

3. Repetition från lektion 97: anropet är GET /customers/9b801085-b120-4eba-b9ed-5b7841385dd4. Var står id:t i eventet?

Sammanfattning

  • Ett UUID är ett id på 32 tecken i fem grupper. I version 4 slumpas nästan alla tecken.
  • randomUUID() ur den inbyggda modulen node:crypto ger ett nytt UUID som sträng, och koden skapar id:t själv, inte databasen.
  • Ett löpnummer går att räkna fram, ett UUID gör det inte. Ägarkontrollen behövs ändå.

Källor

Huvudkälla: Node.js: crypto.randomUUID().

Om formatet: RFC 9562: Universally Unique IDentifiers (UUIDs).
