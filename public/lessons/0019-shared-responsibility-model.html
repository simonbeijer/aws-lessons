Lektion 19

Shared Responsibility Model

Vad du ska veta efter lektionen Vad AWS ansvarar för och vad du ansvarar för, med S3 och Amplify som exempel.

Vad är Shared Responsibility Model?

Shared Responsibility Model är AWS beskrivning av hur säkerheten delas mellan AWS och dig. AWS ansvarar för säkerheten av molnet, du för säkerheten i molnet. (AWS: Shared Responsibility Model)

Säkerheten av molnet är infrastrukturen, alltså datacenter, maskiner och nätverk som alla AWS-tjänster körs på. Hur mycket som är ditt beror på vilken tjänst du använder. (AWS: Shared Responsibility Model)

Vad du ansvarar för i S3

I S3 ansvarar du för din data och för vem som får komma åt den. (AWS: Security in Amazon S3)

AWS låter spärren vara på från början. Stänger du av den är det ditt val.

Du skriver vem som får läsa. Med Principal "*" kan alla läsa allt i bucketen.

Laddar du upp personuppgifter i en publik bucket är det ditt ansvar, inte AWS. (AWS: Security in Amazon S3)

Var gränsen går i Amplify

Gränsen går vid det du lägger in: kod, inställningar och data är ditt. Maskinen som bygger appen är AWS ansvar. (AWS: Security in Amplify, AWS: Data protection)

AWS

Datacenter, maskiner och nätverk. Maskinen som kör bygget.

Du

Din kod och data. Vem som får komma åt dem.

Varning

Hamnar ett lösenord i din kod eller byggets logg är det ditt ansvar. AWS varnar för att det du skriver in kan hamna i loggar. (AWS: Data protection)

Quiz

1. Du laddar upp en fil med personuppgifter till en publik bucket. Vems ansvar är det?

2. Amplify bygger din app på en maskin hos AWS. Vem ansvarar för maskinen?

3. Repetition från lektion 13: hur ser Block Public Access ut i en ny bucket?

Sammanfattning

  • AWS ansvarar för säkerheten av molnet: datacenter, maskiner och nätverk som tjänsterna körs på.
  • Du ansvarar för säkerheten i molnet: din data och vem som får komma åt den, till exempel Block Public Access och bucket policy.
  • I Amplify är byggmaskinen AWS ansvar. Din kod, dina inställningar och det som hamnar i loggen är ditt.
